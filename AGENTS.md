# Repository Guidance

## Start here

1. Read `docs/VALIDATION_PLAN.md` for the current M5 P1-A sub-hour temporal integrity and prioritized validation backlog.
2. M4.5 is terminal: `.agent-run/LR-20260914-FSL-M45-001/RUN_STATE.md` is historical audit context, not an active campaign. Verify its Task Packet SHA-256 when auditing it; do not create another M4.5 closeout cycle.
3. Check the current branch, HEAD, remote, and working tree before editing.
4. Preserve unrelated or pre-existing changes.

## Architecture

- UI: Vite + React + TypeScript in `src/app/`.
- Calculation engine: Pure TypeScript in `src/engine/`.
- Domain types: `src/models/`.
- Weather ingestion and normalization: `src/weather/`.
- Facade geometry primitives: Pure TypeScript in `src/geometry/`.
- Comparison cases, deltas, and input differences: Pure TypeScript in `src/comparison/`.
- Multi-floor composition, aggregation, presets, and exports: Pure TypeScript in `src/multifloor/`.
- Never import React, DOM, Canvas, or browser globals into the calculation engine.
- Keep core calculations deterministic and usable from Browser, Node.js, batch tests, and validation scripts.
- Keep the original-source reference generator independent from `src/engine/`; expected Golden values must never be generated by the new engine.
- Keep `legacy-v01` and `weather-v1` separate; neither engine may silently call or rewrite the other.

## Domain constraints

- Declare units at module boundaries. Prefer SI internally; never mix mm and m implicitly.
- Define angle convention, facade azimuth convention, time zone, and coordinate system explicitly.
- Use tolerances for geometry and floating-point comparisons.
- Shading geometry with a window-head offset depends on both `D/H` and `O/H`.
- Do not present unvalidated absolute `[kWh]` results as formal performance evidence.
- Keep weather-source provenance visible; do not disguise empirical factors as physical models.
- Treat M1 absolute `[kWh]` values only as `LEGACY BASELINE / NOT VALIDATED PHYSICAL MODEL` regression data.
- EPW uses Local Standard Time and interval-end radiation in `Wh/m2 interval`; evaluate weather-v1 geometry at the interval midpoint without `Date`, DST, or host-timezone dependence.
- Reject missing/invalid required solar data by default; never silently zero-fill it.
- Facade-local coordinates use wall `y = 0`, front-view `+x` right, outward `+y`, and `+z` up; azimuth is north-zero/clockwise.
- Keep M3 finite-width geometry limited to direct shadow; its diffuse model remains the explicitly identified M2-compatible 2D infinite-width approximation.
